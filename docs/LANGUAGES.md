IRIS language and GitHub Linguist mapping
=======================================

This file documents how the IRIS language is mapped and submitted to GitHub Linguist.

Vendored grammar
- We vendor a TextMate grammar for IRIS when submitting to Linguist. The vendored grammar is placed under `vendor/grammars/iris-tmLanguage/` in the Linguist repository and includes:
  - `syntaxes/iris.tmLanguage.json`
  - `LICENSE`
  - `README.md`

Language metadata
- The authoritative registration for IRIS in Linguist is in `lib/linguist/languages.yml` (in the Linguist repo). The important fields are:
  - `extensions`: includes `.iris` and any auxiliary extensions
  - `tm_scope`: `source.iris` (must match the TextMate grammar scope)
  - `aliases`, `interpreters` and other display fields
  - `language_id` is generated by `script/update-ids` and should not be hand-assigned

Current language id
- The `script/update-ids` helper assigned `language_id: 817425607` for IRIS when the patch was prepared.

Heuristics
- A small heuristics entry was added to `lib/linguist/heuristics.yml` to disambiguate `.iris` files from other uses of the extension. This helps Linguist classify repositories more accurately.

Updating the grammar or metadata
- Steps to update the vendored grammar and metadata:
  1. Update the upstream TextMate grammar (source in this repo under `iris-tmLanguage/syntaxes/`).
 2. Re-run `tools/generate_iris_linguist_patch.py` to regenerate `tools/iris-linguist.patch`.
 3. Apply the patch to a local clone of the Linguist repo and vendor the grammar under `vendor/grammars/`.
 4. Run Linguist helper scripts (recommended in Docker): build image in `tools/linguist-docker/`, mount the Linguist checkout, run `bundle install`, then `script/update-ids`.
 5. Run `rake test` in the Linguist checkout and review failures — many repository tests are unrelated to grammar changes; if CI fails for unrelated reasons, file a follow-up or ask maintainers for guidance.

Notes
- CI for forked PRs usually requires a maintainer to approve and run Actions before GitHub executes workflows. This is normal for security reasons.
